# 联机协议（MineWeb）

服务端：`tools/server.mjs`，**零依赖**。同一端口既提供静态文件，也接受 WebSocket 升级，
所以局域网联机只需要：

```bash
node tools/server.mjs 8138
# 其他人打开 http://<你的IP>:8138/ ，游戏里执行
/connect ws://<你的IP>:8138/
```

客户端实现：`js/net/client.js`；游戏内接入在 `js/game/game.js` 的 `connectToServer()`。

## 为什么手写 WebSocket

Node 自带 WebSocket **客户端**，但没有服务端；本项目不引入任何依赖。
因此只实现游戏用得到的部分：文本帧、ping/pong、close。
二进制帧与分片控制帧会被明确拒绝，而不是猜测处理 —— 宁可报错也不要静默错位。

## 消息格式

全部是 JSON 文本帧。

### 客户端 → 服务端

| 消息 | 字段 | 说明 |
|---|---|---|
| `join` | `name` | 加入；必须在其他消息之前 |
| `move` | `x y z yaw pitch` | 位置与朝向，客户端约 10 Hz 发送 |
| `edit` | `x y z block` | 单个方块改动；`y` 必须在 `0..127` |
| `chat` | `msg` | 聊天，最长 200 字符 |

### 服务端 → 客户端

| 消息 | 字段 | 说明 |
|---|---|---|
| `welcome` | `id seed time players[] edits[]` | 自己的 id、世界种子、当前在线玩家、**全量改动回放** |
| `join` | `id name player` | 有新人加入 |
| `leave` | `id` | 有人离开 |
| `move` | `id x y z yaw pitch` | 他人位置 |
| `edit` | `id x y z block` | 他人改动 |
| `chat` | `id name msg` | 聊天（会回显给发送者本人） |
| `error` | `msg` | 协议错误 |

## 权威性

**服务端是唯一权威**：它持有种子与改动日志（`net-world.json`），新玩家加入时通过
`welcome.edits` 拿到全量回放，因此后来者看到的建筑与先来者一致。

进程内每次改动都**同步落盘**。不用防抖的原因是 Windows 上 `kill` 走的是
`TerminateProcess`，定时器和退出钩子都不会执行，防抖会静默丢掉最后一段日志。

## 已知限制（诚实说明）

- 只同步**方块改动**与**玩家位置**；生物、掉落物、熔炉/漏斗状态、时间流逝各自独立
- 没有身份验证与权限，任何能连上端口的人都能改动世界；只适合局域网或自建环境
- 没有做客户端预测与冲突消解：两人同时改同一格时，以服务端最后收到的为准
- 世界地形由种子各自生成，`welcome.seed` 不一致时客户端会提示"地形可能对不上"

## 自检

```bash
node tools/net-test.mjs 8139
```

它会启动临时服务端、连两个客户端，验证：加入/欢迎、改动转发、位置与聊天转发、
后加入者收到改动回放、越界改动被丢弃、重启后日志仍能回放。
